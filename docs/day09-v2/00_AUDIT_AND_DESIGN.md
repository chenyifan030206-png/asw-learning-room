## 3. 当前 D09 已证实的设计问题

1. `courses.json` 当前 D09 涵盖主课周期/dt及补回原 D08 的信号时效，`run_fields` 共 8 字段，`experiments` 共 13 项（主课 7、附录 6），`assets` 共 10 文件（主课 6 项：5 个工程文件加 README；附录 4 个工程文件）。主题混合使注意力和练习负担过高。
2. `index.html` 顶部有云同步、路线等大块内容；课程内又先显示全部源码，随后才是执行步骤；初学者需要反复上下滚动才能知道引用的是哪行。
3. `app.js` 的 `showStep()` 通过源码子串 `indexOf(start/end)` 截取，可能因重复字符串、格式变化或结束锚点定位产生不稳定范围；章节左侧实际完整源码文件与右侧逐段讲解的文件选择也未建立可靠的一一联动。
4. D09 的 `code_sections` 为 10 段，但多数解释正文仅数十字，没回答 `struct Timeline draft = {0};` 和 `result.control_count` “第一次在哪定义、为什么用点号、什么时候被写入”。
5. 多处使用“接待员/观察员/账本/两份按时做的工作”等拟人隐喻，但实际术语“main 输入/计算函数/输出结构体/周期更新时刻”没有持续固定；容易出现“比喻比代码还难找对应”的问题。
6. `reading` 以换行分段 `textContent` 插入段落，结构化表格/内嵌代码定位/逐步状态可视化未充分建立；CSS 的 `pre` 高度与文本侧栏也没有保证长代码与解释在同一视线。
7. 原课的 `timeline` 逻辑以离散纸面时刻模拟，不是真正 OS 定时调度。此边界必须保持醒目，不能宣称证明真实 10ms 实时性。
8. D08 实际教学为 memset/内存，与先前计划“信号时效”不一致。**必须保留 D08 补课需求，但从 D09 主线拆分**，不得悄悄宣称完成或并入 D09 通关。

## 4. D09 v2 唯一核心目标

> 理解：速度不变时，一段距离 = 速度 × 两次有效更新之间的真实时间间隔；漏掉30ms的更新，40ms那次应使用20ms而不是继续假定10ms。

只需手算一个例子：

- 计划时刻：0、10、20、30、40、50、60ms。
- 速度恒定：10m/s；每10ms为0.10m。
- 不漏：6段×0.10=0.60m。
- 漏掉30ms：控制实际记录0、10、20、40、50、60；实际dt=0、10、10、20、10、10ms。
- 错误固定dt算法：5×0.10=0.50m；依据实际dt：10×(10+10+20+10+10)/1000=0.60m。
- 这只是恒速位移积分示例，**不代表漏掉一次控制决策后可以保证补回控制功能或安全性**。

D09 不新增 bit、DBC、诊断协议、ROS 实际调度，也不把数据年龄/来源叠加到主线。

## 5. 必须补足的“符号来源与调用地图”

第一屏必须有下表，且每项能点开精准定位源代码；不得让学习者自己搜索：

| 名字/表达式 | 首次定义位置 | 类型/角色 | 后续用途 |
|---|---|---|---|
| `struct Timeline` | `timing.h` | 结构体类型 | 规定控制时间、dt、统计量成员 |
| `control_ms[7]` | `timing.h` 的 Timeline 内 | int 数组成员 | 保存有效控制到场时刻 |
| `dt_ms[7]` | `timing.h` 的 Timeline 内 | int 数组成员 | 保存与上一次有效控制到场的时间差 |
| `control_count` | `timing.h` 的 Timeline 内 | int 成员 | **已记录的到场行数，包含0ms初始化行** |
| `result` | `demo.c` 的 main | `struct Timeline` 对象 | 接受输出、由 main 用 `result.control_count` 读取 |
| `Timeline_Run` | 声明在 `timing.h`；定义在 `timing.c` | 函数 | 由 `demo.c` 的 main 调用 |
| `out` | `timing.c` 的 `Timeline_Run` 形参 | 结构体指针 | 指向 main 的 result |
| `draft` | `timing.c` 的 `struct Timeline draft = {0};` | **局部结构体对象，不是指针** | 先计算，成功后 `*out = draft` |
| `draft.control_count` | draft 的结构体成员 | 计数变量 | 当前写入的下标来源；记录后自增 |
| `last_control_ms` | `timing.c` 的 Timeline_Run 内 | int 局部变量 | 记录上一次实际执行控制的时刻 |
| `tick` | `timing.c` 的 for 循环 | int 局部变量 | 0到6的**计划序号**，不是时钟本身 |
| `scheduled_ms` | `timing.c` 的循环体 | int 局部变量 | tick×10得到计划到场时刻 |
| `now_ms` | `timing.c` 的循环体 | int 局部变量 | 本轮实际记录时刻，可包含迟到 |
| `elapsed_ms` | `timing.c` 的 if(index>0) 内 | int 局部变量 | now−last，单位ms |
| `dt_s` | `timing.c` 的 if(index>0) 内 | float 局部变量 | elapsed_ms/1000，单位s |

区分：`result.control_count` 与 `draft.control_count` 是**两个结构体对象各自的同名成员**。成功前只修改 draft，成功后执行 `*out = draft;` 整体复制值给 main 的 result。因此 main 才能读取 result 的更新后成员。

## 6. 教学顺序（按学习者滚动阅读方式组织）

**第0屏：目的与一个示例（不超过一屏）**
- 一句话任务、一张时间轴、三项输入解释、两项预测结果。
- 提问“漏掉30ms，下次40ms应该用多少dt？”，先让学习者回答，随后展示为什么20ms。

**第一屏：完整工程总览（入口优先）**
- 列出5个主课文件，但只展开`demo.c`→`timing.h`→`timing.c`，测试与CMake收进独立“工程扩展”。
- 包含固定的“函数与变量来自哪里”大表，点击符号跳转到定义行与使用行。
- 先展示完整源码入口，后讲调用过程；用户可随时查看任一文件完整源码，不强迫从第一行头文件阅读。

**第二屏：按真实执行顺序**
1. demo.c 的 main 读取 `speed_mps,skip_tick,late_ms`。
2. 创建 `struct Timeline result = {0};`，说明类型定义在 timing.h。
3. 调用 `Timeline_Run(...,&result)`，参数逐项对照。
4. 进入 timing.c：参数验证→创建 draft→for 循环。
5. 用“漏掉30ms”逐轮表详细解释 `continue`、`index`、`last_control_ms`、`elapsed_ms`、`+=`。
6. `*out = draft; return 0;` 后回到 demo.c 展示结果。

**第三屏：再看代码中每个符号**
- 每个符号统一用“第一次出现位置→是什么类型→为什么需要→本次取值→修改影响”五格卡。
- 每次只解释当前选中代码段，符号来源表固定可见。

**第四屏：实验、检测、真实编译**
- 主线仅 4 个必做：正常、漏30ms、迟到5ms、参数非法。原 M04/M05/M07 可保留为迁移题，不作为理解第一遍的强制门槛。
- 一道未见过的迁移题（比如20m/s漏30ms）独立手算，不以刷完预设按钮代替掌握。
- 保留浏览器模拟明确提示；真实 GCC/CMake/CTest 证据须单独显示、不得与模拟混淆。

**独立补课 D08A：信号年龄**
- 与本主课物理拆分，单独页面/课程标签/单独进度项；保留已有附录记录与链接。
- D09 通关与 D08A 待补互不混淆。

## 7. 页面排版准则

1. 课程优先，云同步与路线默认折叠；不要让用户进入 Day09 后先跨越两屏账户设置。
2. 桌面阅读区：左边为完整源码并可定位行号，右边为当步解释、值变化与变量来源；两侧滚动独立、当前位置始终可见。笔记可以折叠到右抽屉，不能挤窄主讲解区。
3. 移动端单列切换“源码 / 执行解释”，保留当前步、当前文件、代码行号，不出现横向页面滚动。
4. C代码采用成熟语法高亮；注释每个**逻辑块**一条即可，逐行原因放侧栏，不要整屏“机翻式括号注释”。
5. 清楚区分：定义处、赋值处、函数调用处、使用处；符号点击或悬停可以跳转，必须有键盘可用的等价交互。
6. 时间轴及逐轮表固定单位：ms、s、m/s、m；速度与时间不混单位。时间是**模拟给定的计划/到场时刻**，不由浏览器/CPU性能测得。
7. 简洁词汇统一：控制更新、传感更新、时刻、时间差dt、固定dt、实际dt、结果结构体。禁止混用“账本/观察员/接待员/工作安排”等拟人角色。
8. 代码完整展示并可下载；展开的片段必须映射到准确原文件/起止行，不能仅靠任意字符串匹配猜行号。
9. 单位/定义/示例数据三者相邻，避免先出现新术语、三屏以后才解释。

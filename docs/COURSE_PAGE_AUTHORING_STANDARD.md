# 84天智驾学习室 · 页面制作与教学质量规范

版本：2026-11-19。适用范围：今后全部 Dxx 主课、独立补充课及既有课程重构。**本文件规范产出与审查过程，不要求每一天使用同一排版或固定教学顺序。**

## 第一阶段：先查学习目标，再决定今天讲什么

1. 读取 `courses.json.curriculum[day-1]` 中的原定主题、前置知识、实作、故障注入与验收；核对已发布前一日的源码、习题和用户反馈。不得因为学生前一天问过某个知识点，就把下一课改成该知识点的重讲。
2. 将知识分为「必须懂」「用于操作」「后续再学」三级；严格检查会不会在尚未讲解前使用新符号、新函数或新单位。
3. 建一张 **依赖顺序表**（前一概念为何引出下一概念）。将每一节划分为：具体问题 → 为什么现有理解不够 → 示意图或手算 → 推导与单位 → 程序化表示 → 迁移应用。
4. 按学习者现有能力制定深度：已有 C 基础，但 Python 是零基础的新语言；类比可以减轻陌生感，不能代替 Python 语法拆解。
5. 为学生的完整课后反馈建立「已懂 / 仍不清楚 / 尚未验证」记录。没有新增笔记就不要杜撰弱点。

## 第二阶段：依据内容的学习方式决定页面形态

| 主题性质 | 内容优先顺序 | 必要图/演示 | 最终实作 |
|---|---|---|---|
| 理论／数学（如 D16） | 现实场景→坐标/物理直觉→图示→推理→公式→代码实现 | 同一例子的逐步图、坐标轴、单位、关键中间量；可交互但须有静态说明 | 数值手算、故障对比、代码和测试 |
| 编程语法（如 Python 初学） | 最小完整语句→符号逐词解析→逐行/逐轮执行→对照 C→修改练习 | 代码行和变量值表，必要时小流程图 | 本地运行、改输入、预测输出 |
| 软件架构（如 D12–D14） | 具体需求→文件职责→接口契约→时序/数据流→完整代码→故障 | 可定位的模块关系、请求/返回路径与状态表 | 真实源码、故障注入、测试 |
| 实验／数据（如 D15） | 输入样本与单位→质量规则→处理链→计算→可视化→错误定位 | 数据表/坐标图，标真实和模拟来源 | 正常与异常样本、可重复运行 |
| 综合考核 | 需求→评分准则→独立实作→边界问题→总结薄弱点 | 按任务需要 | 不预先给全套解答，保留验收记录 |

不要把每课都做成“先放完整代码、再贴一句解释”的模板。对基础数学，讲解理论图和数值推导必须出现在完整工程代码之前；对架构课，接口关系可以在代码前，但必须说明每个接口的输入输出。

## 第三阶段：撰写讲义的最低质量要求

每个新概念至少回答五个问题：

1. **它在解决什么问题？** 给一个读者不用懂函数也能理解的实际情境。
2. **它究竟表示什么？** 把符号、单位、坐标约定、输入与输出说清楚。公式中的每个字母在首次使用时定义。
3. **为什么计算是这样的？** 最少一个具体数字的逐步演算，解释中间结果及符号/运算顺序。不要只给结论。
4. **它在 Python/C 中怎样实现？** 与真正源代码一一对应；不要凭图编造函数逻辑。逐条解释“调用者、形参、返回对象、数组维度、异常”。
5. **如何知道它正确或发现错误？** 给独立于程序实现的预期、边界和故障注入。清楚标明浏览器的 JS 模拟与本地真实程序。

**不以字数灌水**，但不能仅用一句话代替推导。讲述相邻概念时必须让前一节的待解问题自然引出下一节。术语第一次出现应解释，之后用统一称呼；不反复英译，不用机翻句式。

- 例如写「把车体坐标中的点转换为世界坐标」，不写「执行世界化的向量变换操作」。
- 写「从矩阵中取出左上角的两行两列」，再指出代码 `T[:2, :2]`；不能只有「切片取子矩阵」。
- 写「将每个点扩展成三个数字，最后一个写 1，让平移能够参与矩阵乘法」，再引入「齐次坐标」；不要先抛术语。
- 中文代码注释要解释**为什么这样写**及参数、单位、特殊值；不要为每条自明赋值机械注释。允许必要数学记号 `R`、`T`、`@`、`shape`，首次出现解释。

## 第四阶段：设计图文关系与交互

- 每张图明确题注、坐标方向、原点、单位、色彩含义、输入/输出。尽量使用与紧邻公式一致的数值；采用示例且不当作真实车载测量。
- 新的概念图首先可以单独看懂，再用于支撑公式。用连续过程展示同一个点的坐标变化，避免更换场景导致读者无法对照。
- 交互控件真实改变图与数值，并提供离散默认状态；无需点击也能理解。不同图不能给相反的角度或坐标约定。
- 配图优先原生可复现 SVG/Canvas 或经审核的原创图，移动端不能横向溢出；保留文本替代说明、键盘可操作输入和明确的图注。
- 图示计算不得假装执行 C/Python/实时车辆模型；网页 JS 数值演算必须与本地源码用同样定义做对账。

## 第五阶段：代码与实验组织

- 先搭起清楚且可运行的最小计算，然后给出完整工程及入口 → 导入模块 → 函数调用 → 返回 → 输出/异常。
- 用户可以从完整文件、具体代码行和理论段落三条路径定位到同一个概念。代码旁解释依次为：语句含义、具体值的变化、为什么这里需要它、误用后的表现。
- 完整源码、中文说明、README、依赖和真正运行测试都在下载包中；交互案例的 JS 不是 Python 本身。
- 对于理论课，通关包括数值手算、工程运行、故障注入与逆向检验；只有浏览器成功才算在线通过。
- 保留原 `lesson.source`、`code_sections`、资产下载、编号问题、个人源码注释、笔记自动保存与恢复。任何改变必须有回归测试。

## 第六阶段：验收、发布及回退

在创建/合并 PR 之前，逐项检查：

- 内容：课程排序与原路线一致；先修知识没有跳跃；公式、变量、单位与实际源码一致。
- 数学：真实 Python/NumPy 执行，独立期望值与逆变换闭环检查；故障输入不发布有效结果。
- 图示：符号/坐标/数值核对，含图题与替代文字；桌面及手机下可阅读；交互改变图和计算结果。
- 阅读：视觉上先看到当前课需要的概念图/理论，再看到代码；不是只在 JSON 里改顺序却页面依旧代码优先。
- 数据：所有既有用户笔记、划线、个人文件副本及通关来源可在刷新后恢复，不能在初始化逻辑中覆盖。
- 工程：构建测试、旧课回归、真实浏览器按键与 ZIP 验证；仅在通过后合并 main 并确认 Pages 部署 `success`。

保留原版课程记录；版本号和入口缓存参数同步变更，必要时提示“刷新课程资源（保留笔记）”。

## D18起新增：零基础外部API教学与反馈闭环（2026-11-24）

每课先列出实际源码中所有非自定义函数、方法、类型、属性与首次出现的语法，按标准库、NumPy、Matplotlib等分类；对首次接触的项目解释名称、定义、参数（位置/关键字）、返回类型与shape、最小独立输入输出、为何用于当前问题及常见误用。不可只翻译英文名称。已经学过的项目可简短复习并指向此前课程。未确定是否掌握时按新手处理。

所有新增API的解释必须写入实际源文件的中文注释，并提供独立的 FUNCTION_GUIDE.md（在网页文件浏览、项目ZIP和仓库内均可读）。测试与绘图代码也应解释新API；教学用自定义函数与库函数明确区分。验收检查网页资产与仓库原文件逐字一致、参考手册在ZIP内、实际函数运行结果与示例一致。

D17反馈“误差和噪声的关系”是D18切入点：区分真值、测量误差、偏差、随机噪声和离散误差；不把批注当作未掌握全部D17的证据，不改旧课的批注定位、个人源码或进度键。D18先讲实际读数、统计量和滤波递推，再比较固定种子噪声和独立无噪声阶跃，最后读代码；D19卡尔曼滤波留待下一课。
